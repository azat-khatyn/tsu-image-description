# LLM-as-judge rubric

**Версия:** 0.1 (placeholder, до pilot прогона I-6)
**Статус:** ЧЕРНОВИК. Замораживается ДО запуска экспериментов E-x. После pilot прогона на baseline-описаниях правки рубрики разрешены; после freeze — нет.

**Назначение.** Третий сигнал триады из §4.1 [docs/experiments.md](experiments.md). LLM получает изображение открытки и сгенерированное описание, оценивает его по фиксированным критериям. Используется как measurement instrument, не как источник истины.

**Модель:** Claude Sonnet 4.6 (по умолчанию). Не меняется в ходе серии экспериментов.

---

## Критерии (5 × 1–5 шкала)

### 1. Faithfulness (точность)
Соответствует ли описание тому, что реально изображено?

- **5** — все объекты и сцены, упомянутые в описании, видны на изображении.
- **3** — большинство деталей верны, но есть мелкие неточности.
- **1** — описание содержит грубые ошибки или галлюцинации.

### 2. Completeness (полнота)
Упоминает ли описание ключевые визуальные элементы открытки?

- **5** — описание покрывает основной сюжет, тип, стиль и заметные детали.
- **3** — основной сюжет есть, но детали или стиль упущены.
- **1** — описание слишком общее, ключевые элементы отсутствуют.

### 3. Style (стилевая уместность для библиотечного каталога)
Подходит ли язык и форма описания для архивного каталога?

- **5** — нейтральный описательный стиль, без оценочности, грамматически корректен.
- **3** — стиль приемлем, но есть стилистические шероховатости (повторы, разговорность).
- **1** — стиль неподходящий: эмоциональный, разговорный, или с грамматическими ошибками.

### 4. No-hallucinations (отсутствие выдумок)
Содержит ли описание утверждения, не подтверждаемые изображением?

- **5** — нет утверждений, не следующих из изображения.
- **3** — есть одно сомнительное утверждение, не критичное.
- **1** — есть очевидные выдумки (сцены, объекты, контекст которых нет на изображении).

### 5. Brevity & informativeness (компактность и информативность)
Соблюдён ли баланс между краткостью и полезностью для поиска?

- **5** — 1–3 предложения, каждое несёт информацию для поиска.
- **3** — описание либо слишком короткое (< 5 слов), либо слегка раздуто.
- **1** — описание либо односложное (1–2 слова), либо содержит много "воды".

## System prompt (черновик, замораживается до запуска E)

```
Ты — библиотечный каталогизатор. Тебе показывают изображение открытки из архива и сгенерированное описание.
Твоя задача — оценить описание по 5 критериям, каждый по шкале 1–5.

Критерии:
1. Faithfulness — точность по отношению к изображению
2. Completeness — полнота: упомянуты ли ключевые визуальные элементы
3. Style — стилевая уместность для библиотечного каталога
4. No-hallucinations — отсутствие выдуманных деталей
5. Brevity — компактность при сохранении информативности

Верни ответ строго в JSON формате:
{
  "faithfulness": <int 1-5>,
  "completeness": <int 1-5>,
  "style": <int 1-5>,
  "no_hallucinations": <int 1-5>,
  "brevity": <int 1-5>,
  "justification": "<1-2 предложения о ключевых наблюдениях>"
}

Будь строг и последователен. Не делай скидок на то, что описание автоматически сгенерировано.
```

## Aggregation

`LLM-judge score` для одного описания — **среднее по 5 критериям**, диапазон [1.0, 5.0].
Для агрегации по eval pool — среднее по всем образцам.
В отчёт также включается per-criterion breakdown (помогает понять, где именно проигрывает модель).

## Калибровочный pilot (до freeze)

После реализации I-6:

1. Прогнать судью на 10 baseline-описаниях из текущего eval set (20 открыток).
2. Вручную просмотреть оценки и justifications. Если judge систематически:
   - даёт 5 за всё → ужесточить criteria descriptions;
   - игнорирует hallucinations → усилить пункт 4;
   - даёт нерелевантные justifications → переписать промпт.
3. После трёх возможных правок — freeze. Дальнейшие правки запрещены до конца серии E.

После freeze датируем эту версию документа и фиксируем в `experiments_log.md`.

## Semantic Density Score (SDS) — axis-rubric

**Назначение.** Четвёртый reference-free сигнал (см. раздел 2, П3). Измеряет покрытие
описанием шести семантических осей, релевантных архивному поиску. В отличие от
основной 5-балльной рубрики выше, по каждой оси выставляется **бинарный** индикатор
покрытия (0/1).

`SDS(d) = (1/6) · Σᵢ I(d, aᵢ),  SDS ∈ [0, 1]`

### Оси и критерий присутствия

| # | Ось | Индикатор = 1, если описание содержит... |
|---|---|---|
| a₁ | **Тип материала** | Явное название архивного типа: открытка / плакат / иллюстрация / фотография / гравюра / поздравительная карточка |
| a₂ | **Визуальный сюжет** | Конкретное описание того, что изображено: люди, объекты, сцена, действие. Каталожно-абстрактные фразы ("изображение", "композиция") без объектной конкретики не засчитываются |
| a₃ | **Художественный стиль** | Указание техники или художественной манеры: винтаж / ретро / гравюра / живопись / рисунок / чёрно-белая фотография / цветная фотография / декоративная иллюстрация |
| a₄ | **Эпоха / период** | Хронологическая привязка: век, десятилетие, обозначение периода ("конец XIX века", "1910-е", "дореволюционный") |
| a₅ | **Культурно-исторический контекст** | Указание контекста сюжета: религиозный / праздничный (Рождество, Пасха, Новый год) / городская / сельская / военная / семейная сцена. Указание просто типа сцены без культурной привязки не засчитывается |
| a₆ | **Эмоциональный тон** | Явная характеристика настроения: радостное / праздничное / романтическое / ностальгическое / спокойное / серьёзное |

### System prompt для LLM-режима

```
Ты — библиотечный каталогизатор. Тебе показывают изображение открытки и сгенерированное
описание. Твоя задача — определить, покрывает ли описание каждую из 6 семантических осей,
существенных для архивного поиска.

Для каждой оси верни 1, если описание явно содержит соответствующую информацию,
и 0 — если ось не покрыта или покрыта только косвенно. Будь строг: косвенные намёки
и общие фразы не засчитываются.

Оси:
1. type_of_material — явно назван тип архивного материала (открытка, плакат,
   иллюстрация, фотография, гравюра).
2. visual_subject — конкретно описано, что изображено (люди, объекты, действия,
   сцена). Абстрактные слова "изображение", "композиция" без объектной конкретики
   не засчитываются.
3. artistic_style — указана техника или художественная манера (винтаж, ретро,
   гравюра, живопись, рисунок, чёрно-белая фотография, декоративная иллюстрация).
4. epoch — есть хронологическая привязка (век, десятилетие, период).
5. cultural_context — указан культурный контекст сюжета (религиозный, праздничный,
   городская/сельская/военная/семейная сцена). Просто "сцена" без культурной
   привязки не засчитывается.
6. mood — явно охарактеризован эмоциональный тон (радостное, торжественное,
   ностальгическое и т.п.).

Верни строго JSON:
{
  "type_of_material": 0|1,
  "visual_subject": 0|1,
  "artistic_style": 0|1,
  "epoch": 0|1,
  "cultural_context": 0|1,
  "mood": 0|1,
  "justification": "<1 предложение>"
}
```

### Ключевые слова для offline-режима (fallback без API)

Для отладки и быстрых прогонов используется keyword-based детекция. Это менее точный
сигнал (false negatives при перифразах), но не требует API и фиксирован.

```python
AXIS_KEYWORDS = {
    "type_of_material": [
        "открытка", "открытки", "плакат", "плаката",
        "иллюстрация", "иллюстрации", "фотография", "фотографии",
        "гравюра", "гравюры", "поздравительная карточка",
    ],
    "visual_subject": None,  # эвристика: caption_ru непуст и содержит ≥ 1 существительное
    "artistic_style": [
        "винтаж", "винтажн", "ретро", "гравюр", "живопис",
        "рисун", "чёрно-белая", "черно-белая", "цветная фотография",
        "декоративн",
    ],
    "epoch": [
        "век", "века", "столети", "1800", "1900", "1910", "1920",
        "1930", "1940", "1950", "дореволюционн", "довоенн",
        "начало xx", "конец xix",
    ],
    "cultural_context": [
        "рождеств", "пасха", "пасхальн", "новогодн", "новый год",
        "религиозн", "храм", "церков", "праздничн",
        "городск", "сельск", "военн", "семейн",
    ],
    "mood": [
        "радостн", "торжеств", "праздничн", "романтическ",
        "ностальгическ", "спокойн", "серьёзн", "серьезн",
    ],
}
```

Замечание: `visual_subject` для keyword-режима оценивается через косвенную эвристику
(непустой caption_ru длиной ≥ 4 слов), поскольку покрытие сюжета определяется наличием
объектов, а не словарём.

### Aggregation

`SDS(d)` для одного описания — доля покрытых осей из 6, диапазон [0.0, 1.0].
Для агрегации по eval pool — среднее `SDS` по всем образцам.
В отчёт также включается per-axis coverage rate (помогает понять, какие оси хуже всего
покрываются текущим пайплайном).

### Freeze policy

После одного pilot-прогона (10 описаний, ручная проверка) рубрика SDS замораживается
синхронно с основной рубрикой выше.
