# Статус проекта — краткий обзор

**Проект:** ВКР, ТГУ, 2026 — Система генерации архивных описаний изображений открыток для электронного каталога РГБ / НЭБ.
**Цель:** автоматически генерировать содержательные русскоязычные описания, пригодные для каталога и архивного поиска.
**Дата обновления:** 2026-05-11

---

## 1. Baseline (исходный пайплайн)

```
Image --> BLIP-base -->  caption_en --> MarianMT --> caption_ru ──┐
        
          SigLIP zero-shot --> {image_type, style, theme, mood} -->  DescriptionBuilder (template) ─► archive_description_ru
```


## 2. Метрики (триада метрик в контексте отсутствия референсных описаний)

Задача оценивается в режиме **отсутствия ground truth** — у РГБ на данный момент нет эталонных описаний открыток.
Поэтому опираемся на три независимых reference-free сигнала:

| Измерение | Метрика                                                                               | Сейчас                                          |
|---|---------------------------------------------------------------------------------------|-------------------------------------------------|
| **Достоверность** (faithfulness) | `CLIPScore_RU(image, archive_description_ru)` через M-CLIP/XLM-Roberta-Large-Vit-B-32 | Реализовано, используется                       |
| **Поисковость** (searchability) | `Recall@1, @5, @10` text→image по пулу n=220                                          | Реализовано, используется                       |
| **Стиль / полнота** (style / completeness) | LLM-as-judge по фиксированной рубрике (например, Claude Sonnet)                       | Реализовано, не запускалось (настроить API key) |

**Дополнительно:** bootstrap CI95, paired bootstrap p-value, latency.

## 3. Пул изображений для evaluation

- **20 РГБ-открыток** (слабые описания в виде заголовков из НЭБ-каталога)
- **+200 NYPL-открыток** (случайная выборка, не связанная с обучающей выборкой для fine-tuning, seed=42)
- **= 220 всего**, единый пул для проверки метрики на retrieval

NYPL картинки используются как retrieval-пул (только изображения, без NYPL `title` — title не утекает в evaluation).

## 5.  Так же экспериментально прогнала пайплан для 8 вариантов конфигов (2 backbone × 4 template_mode) на n=220

| backbone | template_mode | CLIPScore_RU | R@1 | R@5 | R@10 |
|---|---|---|---|---|---|
| BLIP-base | full | 0.280 | 0.16 | 0.38 | 0.46 |
| BLIP-base | full −theme −mood (E-16) | 0.287 | 0.14 | 0.41 | 0.54 |
| BLIP-base | minimal (E-16b) | 0.266 | 0.14 | 0.43 | 0.58 |

| BLIP-large | full (E-1) | 0.288 | 0.21 | 0.42 | 0.49 |
| BLIP-large | full −theme −mood (E-1+E-16) | **0.298** | 0.24 | 0.48 | 0.61 |

Все эксперименты значимы vs baseline по CLIPScore (p < 0.001, paired bootstrap).

## 6. Основные выводы

1. **Trade-off достоверности и поисковости** (главная методологическая находка): шаблон поднимает CLIPScore (общая alignment между текстом и картинкой), но снижает retrieval (одинаковые формулировки делают эмбеддинги похожими → ниже различимость). `caption_only` лучше для поиска; `full −theme −mood` лучше для CLIPScore. Для архивного поиска (наш use case) лучше `caption_only`.

2. **BLIP-large > BLIP-base** на всех template_mode (+0.5–1.0% CLIPScore, +5–7% R@1).

3. **Эффекты E-1 и E-16 аддитивны на CLIPScore, super-additive на retrieval** (R@1: −0.02 + 0.06 → +0.08 в комбинации). С BLIP-base шаблонные фразы несут хоть какой-то сигнал; с BLIP-large они становятся redundant noise.

4. **Размер pool критически влияет на retrieval-выводы:** на n=20 E-16 выглядел улучшением (R@1: 0.70 → 0.75); на n=220 — ухудшением (0.16 → 0.14). Маленький pool обманывает.

5. **Domain consistency:** тренды на rgb (n=20 anchor) и nypl (n=200 pool) совпадают по направлению. Улучшения переносятся между доменами.

6. **CLIPScore-дельты значимы только при n ≥ ~100.** При n=20 paired bootstrap p ≥ 0.25 для всех экспериментов; при n=220 — p < 0.001.
